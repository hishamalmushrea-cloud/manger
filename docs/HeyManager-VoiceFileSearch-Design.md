# هي مانجر — محرك البحث الصوتي عن الملفات وتشغيلها
## وثيقة التصميم المعماري والتنفيذ (v2.2 «صوت الملفات»)

**الحالة:** مُنفَّذة بالكامل في الكود على فرع `arena/019f6e8f-manger` (انظر قسم «خريطة الملفات»).
**المبدأ الحاكم:** كل شيء offline — لا إنترنت، لا مفاتيح API، لا بيانات تغادر الجهاز أبداً. 🔒

# 1) تحليل الوضع الحالي (ما كان قبل هذه الجلسة)

قبل هذه الجلسة كانت البنية تحتوي أساسين قابلين للبناء عليهما لكن بفجوات واضحة أمام رؤيتك:

| القدرة | الوضع قبل الجلسة | الفجوة أمام «شغل أغاني حمود» |
|---|---|---|
| بحث بالاسم «ابحث عن ملف اسمه فاتورة» | ✅ موجود (`FileSearchManager`: MediaStore.Files + مشي مجلدات + ترتيب متسامح) | بدون فهرس دائم، بدون مجلد، بدون فنان |
| «آخر صورة / آخر فيديو / آخر PDF» | ✅ موجود | يفتح عارضاً خارجياً حتى للصوتيات |
| «شغل أغنية فيروز» | ✅ `MusicStrategy` يجد المقطع ويسلمه للمشغل الخارجي | لا تكرار/عشوائي/واصل — المفاتيح الخارجية لا تكفي |
| التحكم أوقف/التالي/السابق | ⚠️ مفاتيح وسائط عامة (تعمل فقط إن كان مشغلاً خارجياً نشطاً) | لا استئناف من موضع، لا حالة داخلية |
| البحث بمعيار **المجلد** | ❌ غير موجود | «من مجلد التنزيلات/المفضلة/الكاميرا» غير مفهومة |
| **الفنان** كمعيار بحث للأغاني | ⚠️ جزئي داخل MusicManager | لا يعمل مع أوامر الملفات المركّبة |
| نتائج متعددة ← سؤال اختيار صوتي | ❌ كان يفتح «الأقرب» مباشرة | الإنسان يسأل قبل أن يختار |
| التعلم من «لا، أقصد الثانية» | ❌ غير موجود | خطوة نحو مساعد يتعلم الذائقة |
| شاشة شفافية للفهرس | ❌ غير موجودة | أن تعرف ما يعرفه مساعدك حق خصوصية |
| الفهرسة الخلفية + مراقبة التحديث | ❌ الاستعلام المباشر فقط | البطء على المكتبات الكبيرة |

**الخلاصة:** بدل هدم شيء، بنينا **طبقة فهرس داخلية + محلل معايير + مشغل داخلي** فوق الأساسين، وأعدنا توجيه المسارات بحيث تبقى القدرات السابقة كما هي احتياطاً (Fallback) عند كل نقطة.

**استراتيجية المواضع في البرلمان (لماذا هذا الترتيب تحديداً):**

1. `PlaybackControlStrategy` قبل الموسيقى: «التالي» يجب ألا تُفهم «شغل شيئاً اسمه التالي».
2. `FileSearchStrategy` قبل `MusicStrategy`: «شغل أغنية **من مجلد التنزيلات**» فيه إشارة ملفات (مجلد) تتغلب على إشارة الموسيقى. و«شغل أغنية فيروز» (بلا مجلد) يتجاوزها لأن canHandle يطلب إشارة مجلد مع كلمة أغنية.
3. الاحتياط محفوظ: كل مسار جديد له بديل قديم (مشغل داخلي→ ACTION_VIEW خارجي، فهرس→ MediaStore حي).

# 4) قاعدة البيانات (Room v6)

### `file_index` — لقطة موحّدة عن كل ملف يهم المساعد

| العمود | النوع | الغرض |
|---|---|---|
| `uriString` (PK) | TEXT | مفتاح مستقر — يعمل لـMediaStore وFileProvider معاً |
| `kind` | TEXT مُفهَرس | AUDIO / IMAGE / VIDEO / PDF / WORD / EXCEL / OTHER |
| `name` / `nameNorm` | TEXT مُفهَرس | الاسم الأصلي + المطبَّع (بلا همزات/تشكيل) |
| `stem` | TEXT | الاسم بلا امتداد — «فاتورة_2024.pdf» يجدها «فاتورة» |
| `artist` / `artistNorm` | TEXT مُفهَرس | معيار «للفنان عيسى الليث» |
| `album`, `mime`, `durationMs`, `sizeBytes` | … | عرض وتشغيل |
| `folder` / `folderPath` | TEXT مُفهَرس | معيار «من مجلد التنزيلات» (اسم + مسار) |
| `dateModified`, `dateAdded` | INTEGER | مكافأة الحداثة في الترتيب + الواجهة |
| `playCount`, `lastPlayedAt` | INTEGER | «الأكثر استماعاً» + ترتيب العادات |
| `lastPositionMs` | INTEGER | **استئناف** «واصل الأغنية» من حيث توقفت |
| `hidden` | INTEGER | زر إخفاء في شاشة المكتبة (خصوصية) |
| `fromSaf` | INTEGER | جاء من مجلد اختاره المستخدم |
| `mediaStoreId` | INTEGER | إعادة بناء الـURI عند الحاجة |

### `file_choice_fixes` — التعلم من التصحيح
`queryNorm (PK) → uriString, at` — عند «لا، أقصد الثانية» نحفظ: هذا الاستعلام مطبَّعاً يقود إلى هذا الملف (+35 نقطة في الترتيب مستقبلاً). زر «نسيان اختياراتي» يمسحه بالكامل.

### الترحيل 5→6
`CREATE TABLE` للجدولتين + 4 فهارس (kind/nameNorm/artistNorm/folder). بيانات v1..v5 تبقى كما هي — ترحيل إضافي صِرف (additive-only)، صفر مخاطرة على المستخدمين الحاليين.

### سياسة بناء الفهرس (متى وكيف)

| المحفّز | الآلية | الكلفة |
|---|---|---|
| أول أمر ملفات بعد >30 دقيقة | `ensureIndexed()` كسول بـMutex (طيران واحد فقط) | مسح كامل مرة واحدة |
| دورية | `FileIndexWorker` كل 12 ساعة (BatteryNotLow) | خلفية فقط |
| إضافة ملف جديد | `ContentObserver` على MediaStore → فحص عاجل | ثوانٍ بعد الإضافة |
| زر «إعادة الفهرسة الآن» | `force=true` | عند الطلب |

إعادة البناء **تحفظ الإحصاءات**: قبل المسح نقرأ (playCount/lastPositionMs/hidden) لكل URI ونحقنها في الصفوف الجديدة — ذاكرة التشغيل لا تُمحى أبداً بسبب إعادة فهرسة.

# 5) آلية البحث (Pseudocode)

```
function parse(command):                      # «الفهم» — من جملة إلى مواصفات
    spec.kinds  ← كلمات النوع (أغنية←AUDIO, صورة←IMAGE, PDF…)
    spec.artist ← regex: «للفنان X» | «فنان X» | «من غناء X» | «للمطرب X»
    spec.folder ← regex: «(من|في|داخل) مجلد(ات)? X» | «مجلد X»
                أو اسم مجلد عربي مباشر (التنزيلات/المفضلة/الكاميرا/واتساب…)
    spec.free   ← الباقي بعد إزالة الأفعال والأنواع والحشو (كلمات بحواف فراغات فقط
                  حتى لا نقتطع «من» من داخل اسم مثل «منير»)
    return spec

function search(spec):
    pool ← DAO.activeByKinds(spec.kinds)             # كل شيء في الذاكرة
    for entity in pool:
        if spec.folder غير فارغ:
            if لا يطابق مرادفات المجلد (folder ⊇ alias أو folderPath ⊇ alias):
                score = -1 ; continue                # قيد صلب: خارج المجلد = استبعاد
            else score += 40
        score += اسم: تام 100 | يحتوي 85 | السيق يحتوي 80 | عكسي 70
        score += فنان: تام 95 | يحتوي 85 | عكسي 75
        score += تغطية الكلمات الحرة × 55
        score += تفضيل متعلَّم (نفس الاستعلام)   +35     # التعلم من التصحيح
        score += العادة  min(playCount,5)×3
        score += الحداثة أسبوع +4 / شهر +2
    threshold ← 40 عامة | 1 عندما لا كلمات حرة («افتح الصور» = أرني الشبكة)
    ترتيب: score تنازلي ثم dateModified
    «آخر X» يعيد الترتيب زمنياً صِرفاً · «عشوائي» يخلط
```

**فلسفة التعامل مع تعدد النتائج (مطور نفسياً):**
- نتيجة واحدة ← تنفيذ فوري + ذكر الاسم (شفافية).
- 2–5 (أو أكثر → أفضل 5) ← **لا نختار نيابة عنك**: سؤال مرقّم + قائمة على الشاشة + «قل نعم للأول أو رقم آخر» — والجواب يُفهم ترتيبياً («الثالث» حتى «الخامس» وأرقاماً) أو بالاسم.
- صفر ← سبب مفيد («في مجلد X») + اقتراح قابل للتنفيذ فوراً.
- اختيارك غير الأول يُدرَّس كتفضيل دائم — الذائقة لا تعيد تعليمها.

**ميزانية السرعة (<1 ثانية):** فهرس طازج = 0ms مهيأً؛ قراءة pool على 10k ملف ≈ 15–40ms؛ تقييم ≈ 5–15ms؛ MediaPlayer prepareAsync ≈ 50–150ms. إجمالي p95 أقل من ربع ثانية للأمر بعد الطازج. (الفحص الكامل نفسه 1–4 ثوانٍ لكنه نادر وخارج المسار الحرج).

# 6) آلية التشغيل

| النوع | الآلية | التفاصيل |
|---|---|---|
| صوتيات 🎵 | **مشغل هاي مانجر الداخلي** (MediaPlayer + AudioAttributes مخصص للموسيقى) | قائمة تشغيل حقيقية (مرشحو البحث الـ25)، prepareAsync + seekTo موضع محفوظ، حلقة الإكمال: كرر→أعد نفسه، وإلا→التالي (أو عشوائي)، تلف القائمة بدل التوقف المفاجئ |
| صور 🖼️ | Intent ACTION_VIEW بإذن قراءة URI | معرض النظام الافتراضي |
| فيديو 🎬 | Intent ACTION_VIEW | مشغل النظام الافتراضي |
| مستندات 📄 (PDF/Word/Excel/نص) | Intent ACTION_VIEW مع MIME دقيق | لا يوجد عارض؟ «ثبّت عارضاً مناسباً» بدل الصمت |

**جدول أوامر التحكم الصوتية:**

| الأمر | بدائل اللهجة | ما يحدث فعلاً |
|---|---|---|
| أوقف | اوقف/وقف/سكّر الموسيقى/اقفل | إيقاف مؤقت + **حفظ الموضع** |
| واصل | استأنف/كمّل/تابع/اكمل | ⚡ الأولوية: مشغلٌّ حي ← استئناف فوري. وإلا **إعادة بناء الجلسة** من SharedPreferences+Room (حتى بعد قتل التطبيق) مع الاستئناف من `lastPositionMs` |
| التالي | اللي بعده/بعده/تخطي | شغل التالي (أو مفتاح وسائط للخارجي) |
| السابق | اللي قبله/ارجع | في أول 3 ثوانٍ يعيد المقطع (سلوك المشغلات)، ثم رجوع فعلي |
| كرر | تكرار/اعيدها/ريبيت | تقليب وضع التكرار + إعلان صوتي |
| عشوائي | خلط/شفل/عشوائية | تقليب الخلط |
| ماذا يشتغل الآن؟ | ايش يشتغل/وش يشتغل | «يشغّل X لـY عند الدقيقة m:ss، والتكرار مفعل» |
| افتحها بالمشغل الخارجي | بالمشغل/بمشغل الموسيقى | إيقاف داخلي مؤقت + تسليم المقطع لمشغلك الافتراضي — **أنت حر في مشغلك** |

**اعتراف هندسي صادق (موثق في الكود أيضاً):** المشغل حي داخل عملية التطبيق؛ لو قتل النظام العملية يتوقف الصوت ويكفي «واصل» لاسترجاع الجلسة. الترقية المستقبلية إلى `MediaSessionService` (تشغيل خلفي كامل + إشعار وسائط + أزرار سماعة) مخططة لنسخة «2.5» وليست في هذا المقطع لتقليل سطح الخطر.

# 7) آلية التكامل مع النظام القائم

```
نقاط الحقن (كل واحدة إضافة لا هدم):
 ① CommandResult  ← حقلان جديدان: choiceQuestion, choiceOptions (اختياريان)
 ② MainViewModel.respondOutcome ← نجاح + سؤال اختيار ⇒ pendingClarify=Clarify.Choice + نبرة سؤال
 ③ CognitiveEngine: «نعم» أمام قائمة = الأول · ترتيب الرابع/الخامس · أرقام 1-9
 ④ البرلمان: PlaybackControlStrategy و FileSearchStrategy قبل MusicStrategy
 ⑤ Room v6: جدولان جديدان (ترحيل إضافي فقط)
 ⑥ HeyManagerApplication: دورية الفهرس + ContentObserver
 ⑦ AppScreen: زر مجلد 📁 في الشريط العلوي ← شاشة مكتبة الملفات
```

تتغذى المقاييس الراهنة تلقائياً بلا كود إضافي: `actionKey=file_search` و`playback` تسجَّل في `self_stats` (نسبة نجاح البحث تظهر في «ما نسبة نجاحك؟»)، و`handledBy` العربي يظهر في مركز الأوامر، وإحصاءات الفشل تُشغل محلل الأسباب الحالي (مثلاً فشل إذن صوت ← «افتح التطبيق ووافق عليه»).

### التحديات المتوقعة في Android 10+ (والحلول المُطبَّقة)

| التحدي | لماذا يعضّ؟ | حلّنا |
|---|---|---|
| Scoped Storage — لا مسارات مباشرة | Android 10+ يلغي قراءة المسارات الحرة | MediaStore أولاً + `MANAGE_EXTERNAL_STORAGE` للمستندات (تثبيت مباشر/APK وليس Play؛ لو Play مستقبلاً نكتفي بـMediaStore+SAF) |
| صلاحيات مجزأة (صور≠فيديو≠صوت) على 13+ | رسالة رفض غامضة للمستخدم | بوابة أذونات **لكل نوع** في الاستراتيجية + رسائل عربية دقيقة تقول أي إذن بالضبط |
| الفنان «<unknown>» | بيانات وصفية فقيرة | نرشّح القيم الفارغة و`<unknown>`، ونسقط إلى الاسم/المجلد |
| مجلدات لا يغطيها MediaStore (مثل «المفضلة») | لا موجودة في الجداول | زر «＋مجلد» → تحويل شجرة SAF إلى مسار فعلي + مسح بالملف (لأن لدينا all-files) |
| كلفة الاستعلام المتكرر | بطء+بطارية | الفهرس الداخلي + كسل 30 د + دورية مقيدة بالبطارية |
| قتل النظام لعملية المشغل | توقف غير متوقع | جلسة محفوظة (queue+index+pos) ← «واصل» تعيد بناءها |
| ضجيج ContentObserver | فحص لكل صورة واتساب! | `ExistingWorkPolicy.KEEP` + مهلة الطزاجة 30 د تُهضم الضجيج |
